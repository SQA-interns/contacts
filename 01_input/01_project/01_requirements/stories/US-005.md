# US-005 Tag a Contact

> For: agent (reads), human (reviews) · Owner: Product owner · Agent: read-only

Format: `general/requirements-standard.md`.

## Story

As an Owner or Editor, I want to put free Tags such as `udelezenec2025` or `neObvescaj` on Contacts, so that I can group Contacts into categories.

## Purpose

Tags are the customer's way to categorise Contacts (participants of an event, people who must not be notified). Typing a Tag must be enough: no separate screen to create it (principle 5, simple wins).

## Definitions

| Term | Meaning |
|---|---|
| Tag name | Text of 1 to 50 characters made of letters (of any alphabet [ASSUMPTION]), digits, `-` and `_`, without spaces. |
| `neObvescaj` | A Tag with a special meaning for other tools: "do not notify this person" (Q-32). The product treats it like any other Tag and makes it visible and filterable. |

## Rules

| ID | Rule (EARS) | Source |
|---|---|---|
| R-005-01 | When an Owner or Editor types a Tag name on a Contact and confirms, the system shall put the Tag on the Contact, and shall create the Tag in the Group if the Group has no Tag with that name ignoring upper and lower case (BR-05). | Q-31 |
| R-005-02 | If a Tag name is not a valid Tag name, then the system shall put no Tag on the Contact and show the rule next to the field. | Q-31 |
| R-005-03 | If the Group already has a Tag equal to the typed name ignoring case, then the system shall use that Tag with its existing spelling and create no new Tag. | Q-31 |
| R-005-04 | If a Contact would have more than 50 Tags, then the system shall store nothing and show the limit. | Q-31 |
| R-005-05 | The system shall keep every Tag within one Group: a Tag shall not be shown, suggested or usable in any other Group. | Q-31, Q-20 |
| R-005-06 | When an Owner or Editor removes a Tag from a Contact, the system shall remove only the link; the Tag stays in the Group even if no Contact has it [ASSUMPTION]. | Q-31 |
| R-005-07 | While an Owner or Editor types a Tag name, the system shall suggest the existing Tags of the Group [ASSUMPTION]. | Q-31 |
| R-005-08 | When a Tag is added to or removed from a Contact, the system shall record a History entry (BR-03) and treat it as a save of the Contact (BR-07). | Q-13, Q-38 |
| R-005-09 | The system shall show every Tag of a Contact, including `neObvescaj`, in the contact list and on the Contact. | Q-32 |
| R-005-10 | If a Viewer tries to add or remove a Tag, then the system shall refuse (BR-02) and change nothing. | Q-08 |

## Edge cases

| ID | Input or situation | Expected result | Rules |
|---|---|---|---|
| EX-005-01 | Tag name of 1 / 50 / 51 characters | Accepted / accepted / refused | R-005-02 |
| EX-005-02 | Empty Tag name | Refused | R-005-02 |
| EX-005-03 | `č_š-ž1` | Accepted | R-005-02 |
| EX-005-04 | `a/b`, `a.b`, `a@b` | Refused | R-005-02 |
| EX-005-05 | `Neobvescaj` when `neObvescaj` exists | The existing Tag `neObvescaj` is used | R-005-03 |
| EX-005-06 | The same Tag typed twice on one Contact | Put on the Contact once; no second link | R-005-01 |
| EX-005-07 | Exactly 50 Tags on a Contact | Accepted | R-005-04 |
| EX-005-08 | A stale version number while adding a Tag | Refused with "This contact was changed by someone else" | R-005-08 |

## Out of scope

Renaming and deleting Tags for the whole Group (US-006); filtering by Tag (US-009); sending notifications or e-mail; colours or hierarchies of Tags; a separate screen to create Tags.
