# US-003 Create, view and edit a Contact

> For: agent (reads), human (reviews) · Owner: Product owner · Agent: read-only

Format: `general/requirements-standard.md`.

## Story

As an Owner or Editor, I want to add Contacts with predefined fields and change them later, so that the people and organisations of my Group are in one place.

## Purpose

This is the core of the product. Contacts are kept today in Excel sheets and e-mail lists; without a simple form with the usual fields there is no reason to move. Two Editors must never silently overwrite each other (principle 2).

## Definitions

| Term | Meaning |
|---|---|
| Predefined fields | First name, last name, e-mail, phone, company, job title, street and house number, postal code, city, country, notes. |
| Contact form | The screen where a Contact is created or edited. |

## Rules

| ID | Rule (EARS) | Source |
|---|---|---|
| R-003-01 | When an Owner or Editor submits a new Contact that follows BR-06, the system shall store it in the Group with version number 1 and show it. | Q-29, Q-30 |
| R-003-02 | The system shall offer exactly these predefined fields on a Contact: first name, last name, e-mail, phone, company, job title, street and house number, postal code, city, country and notes. | Q-29 |
| R-003-03 | If a Contact does not follow BR-06, then the system shall store nothing, show a message next to each field in error and keep what the user entered. | Q-30 |
| R-003-04 | When a Contact is saved with an e-mail, the system shall store the e-mail in lowercase. | Q-30 |
| R-003-05 | The system shall trim leading and trailing spaces from every text field of a Contact before checking and storing it [ASSUMPTION]. | Q-30 |
| R-003-06 | When an Owner or Editor saves changes together with the Contact's current version number, the system shall store the changes and raise the version number by 1 (BR-07). | Q-38 |
| R-003-07 | If an Owner or Editor saves a Contact with a version number that is not the current one, then the system shall apply BR-07: refuse the save, show the message "This contact was changed by someone else" and show the current Contact. | Q-38 |
| R-003-08 | When a Member opens a Contact of the Group, the system shall show all its predefined fields, Tags and Attributes. | Q-09 |
| R-003-09 | If a Viewer tries to create or edit a Contact, then the system shall refuse (BR-02) and change nothing. | Q-08 |
| R-003-10 | When an Owner or Editor saves a Contact whose e-mail equals the e-mail of another Contact of the Group, the system shall still store it [ASSUMPTION: duplicates are found later, US-024, not prevented]. | Q-41 |
| R-003-11 | If a save changes no field, then the system shall store nothing, keep the version number and record no History entry [ASSUMPTION]. | Q-40 |

## Out of scope

Import from Excel or CSV; several e-mails or phones per Contact; photos or files; Attributes (US-004); Tags (US-005); deleting (US-012); History and Versions display (US-016, US-022); duplicate prevention.
