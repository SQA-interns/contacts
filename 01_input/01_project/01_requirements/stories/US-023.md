# US-023 Restore an earlier Version of a Contact

> For: agent (reads), human (reviews) · Owner: Product owner · Agent: read-only

Format: `general/requirements-standard.md`.

## Story

As an Owner or Editor, I want to restore an earlier Version of a Contact, so that I can undo a wrong change.

## Purpose

When someone changes a Contact wrongly, the team wants the old state back without retyping it, and without losing the record of the mistake.

## Definitions

| Term | Meaning |
|---|---|
| Restore a Version | Save the content of an earlier Version as a new Version; no Version is removed. |

## Rules

| ID | Rule (EARS) | Source |
|---|---|---|
| R-023-01 | When an Owner or Editor restores an earlier Version of a Contact, the system shall save the content of that Version as a new Version of the Contact (BR-07) and never change or delete an existing Version. | Q-40 |
| R-023-02 | When a Version is restored, the system shall record a History entry that names the restored Version number and the changed fields (BR-03). | Q-37, Q-40 |
| R-023-03 | If the restored content does not follow BR-06, then the system shall restore nothing and show the reason. | Q-30 |
| R-023-04 | If the current version number of the Contact is not the one shown to the user, then the system shall refuse the restore as in BR-07. | Q-38 |
| R-023-05 | When a Tag of the restored Version no longer exists in the Group, the system shall create it again with the same name [ASSUMPTION]. | Q-40 |
| R-023-06 | If a Viewer asks to restore a Version, then the system shall refuse (BR-02) [ASSUMPTION]. | Q-08 |

## Acceptance criteria

| ID | Given | When | Then | Rules |
|---|---|---|---|---|
| AC-023-01 | `Ana Novak` v1 company `Acme`, v2 `Beta`, v3 `Cezar` | An Editor restores v1 | The Contact has company `Acme` as v4; v1 to v3 still exist | R-023-01 |
| AC-023-02 | Same | The History is opened | An entry "restored version 1" with company `Cezar` → `Acme` | R-023-02 |
| AC-023-03 | v1 has only e-mail `ana@x.si`, and BR-06 would still hold | Restored | Accepted | R-023-03 |
| AC-023-04 | The restored content breaks BR-06 (for example an invalid e-mail from a past rule) | Restore | Refused with the reason; nothing stored | R-023-03 |
| AC-023-05 | Boris saved v4 after Ana opened v3 | Ana restores v1 | Refused with "This contact was changed by someone else" | R-023-04 |
| AC-023-06 | v1 had Tag `gost` which was deleted later | v1 restored | Tag `gost` exists again and is on the Contact | R-023-05 |
| AC-023-07 | Viola is a Viewer | She sends a restore | Refused | R-023-06 |

## Edge cases

| ID | Input or situation | Expected result | Rules |
|---|---|---|---|
| EX-023-01 | Restore the current Version | Nothing changes; no new Version | R-023-01 |
| EX-023-02 | Restore a Version of a Contact in Trash | Refused (the Contact is not editable) | R-023-01 |
| EX-023-03 | Version number that does not exist | Not found | R-023-01 |
| EX-023-04 | Restored Version has 50 Tags and the Group has all of them | Accepted | R-023-05 |

## Out of scope

Restoring a single field only; restoring across Contacts; undoing a restore other than by restoring another Version.
