# US-004 Add and change Attributes of a Contact

> For: agent (reads), human (reviews) · Owner: Product owner · Agent: read-only

Format: `general/requirements-standard.md`.

## Story

As an Owner or Editor, I want to give a Contact my own key-value pairs such as `kompetenca=spletnoProgramiranje`, so that I can record what the predefined fields do not cover.

## Purpose

The customer's Contacts differ from project to project; fixed fields cannot cover every need. Without Attributes users fall back to Excel columns again.

## Definitions

| Term | Meaning |
|---|---|
| Key suggestion | A key already used by an Attribute of any Contact in the same Group, offered while the user types a key. |

## Rules

| ID | Rule (EARS) | Source |
|---|---|---|
| R-004-01 | When an Owner or Editor saves a Contact with Attributes, the system shall store each key-value pair with the Contact. | Q-11, Q-34 |
| R-004-02 | If a key is empty or longer than 50 characters, or a value is empty [ASSUMPTION] or longer than 255 characters, then the system shall store nothing and show a message next to the pair. | Q-34 |
| R-004-03 | If a Contact has two pairs whose keys are equal ignoring upper and lower case (BR-05), then the system shall store nothing and show a message next to the second pair. | Q-34 |
| R-004-04 | If a Contact would have more than 50 pairs, then the system shall store nothing and show the limit. | Q-34 |
| R-004-05 | While an Owner or Editor types a key, the system shall suggest the keys already used in the Group, and shall accept any key that follows R-004-02 and R-004-03. | Q-34 |
| R-004-06 | When an Attribute is added to, changed on or removed from a Contact, the system shall record a History entry with the key and the old and new value (BR-03). | Q-13, Q-34 |
| R-004-07 | When an Attribute is added, changed or removed, the system shall treat it as a save of the Contact and apply BR-07. | Q-38 |
| R-004-08 | If a Viewer tries to change an Attribute, then the system shall refuse (BR-02) and change nothing. | Q-08 |
| R-004-09 | The system shall store every Attribute value as text. | Q-34 |

## Acceptance criteria

| ID | Given | When | Then | Rules |
|---|---|---|---|---|
| AC-004-01 | `Ana Novak` has no Attributes | Ana adds key `kompetenca` and value `spletnoProgramiranje` and saves | The Contact shows `kompetenca = spletnoProgramiranje` and its version number is raised by 1 | R-004-01, R-004-07 |
| AC-004-02 | `Ana Novak` has key `kompetenca` | Ana adds a second pair with key `Kompetenca` | Nothing is stored; a message appears next to the second pair | R-004-03 |
| AC-004-03 | `Ana Novak` has 50 Attributes | Ana adds a 51st | Nothing is stored; the limit of 50 is shown | R-004-04 |
| AC-004-04 | Another Contact in the Group has key `kompetenca` | Ana types `komp` as a new key | `kompetenca` is suggested; she may still save the new key `kompetentnost` | R-004-05 |
| AC-004-05 | `Ana Novak` has `kompetenca = spletnoProgramiranje` | Ana changes the value to `java` and saves | A History entry shows key `kompetenca`, old value `spletnoProgramiranje`, new value `java` | R-004-06 |
| AC-004-06 | `Ana Novak` has key `kompetenca` | Ana removes the pair and saves | The pair is gone and a History entry records the removal | R-004-06 |
| AC-004-07 | Viola is a Viewer | She opens `Ana Novak` | She sees the Attributes but has no control to change them; a direct change request is refused | R-004-08 |
| AC-004-08 | Another Group has key `projekt` | Ana types `pro` in `Acme` | `projekt` is not suggested | R-004-05 |
| AC-004-09 | Boris saved `Ana Novak` after Ana opened it | Ana saves a new Attribute | Refused with "This contact was changed by someone else" | R-004-07 |

## Edge cases

| ID | Input or situation | Expected result | Rules |
|---|---|---|---|
| EX-004-01 | Key of 50 / 51 characters | Stored / refused | R-004-02 |
| EX-004-02 | Value of 255 / 256 characters | Stored / refused | R-004-02 |
| EX-004-03 | Empty key | Refused | R-004-02 |
| EX-004-04 | Empty value [ASSUMPTION] | Refused | R-004-02 |
| EX-004-05 | Exactly 50 pairs | Stored | R-004-04 |
| EX-004-06 | Key `delovno mesto` (with a space) and value `vodja` | Stored (the interview limits only the length) | R-004-01 |
| EX-004-07 | Key `kompetenca` on Contact A and `Kompetenca` on Contact B | Both stored (uniqueness is per Contact) | R-004-03 |
| EX-004-08 | Value `<b>x</b>` | Stored and shown as plain text | R-004-01 |
| EX-004-09 | Value `42` | Stored and treated as the text `42` | R-004-09 |

## Out of scope

Typed values (numbers, dates); saved filters; filtering by Attribute (US-009); showing History (US-016); import.
