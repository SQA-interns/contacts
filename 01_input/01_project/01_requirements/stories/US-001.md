# US-001 Register and sign in

> For: agent (reads), human (reviews) · Owner: Product owner · Agent: read-only

Format: `general/requirements-standard.md`.

## Story

As a visitor, I want to register and sign in with my e-mail and password or with my Google account, so that I can reach my Groups.

## Purpose

Every Group belongs to people, and nobody may see another person's Contacts. Without a reliable sign-in the system cannot tell who is asking. Authentication is done by Firebase (Q-21); the product only decides what a signed-in person may do. Priority and MVP are [ASSUMPTION]: the interview names the sign-in but gives no priority; nothing works without it.

## Definitions

| Term | Meaning |
|---|---|
| Verified e-mail | An e-mail address the User has confirmed through the link in Firebase's verification e-mail. |
| Display name | The name shown to other Members and in History. |

## Rules

| ID | Rule (EARS) | Source |
|---|---|---|
| R-001-01 | When a visitor submits the registration form with an e-mail address, a password of at least 8 characters and a display name of 1 to 100 characters [ASSUMPTION: the interview does not say that a name is asked; History needs one], the system shall create the account through Firebase and send Firebase's verification e-mail. | Q-47 |
| R-001-02 | When a visitor chooses "Sign in with Google", the system shall sign the visitor in through Firebase and use the name of the Google profile as display name, or the e-mail address when the profile has no name [ASSUMPTION]. | Q-47 |
| R-001-03 | When a visitor signs in with an e-mail and password that Firebase accepts and the e-mail is verified, the system shall open the Group list. | Q-47 |
| R-001-04 | While the e-mail of a signed-in User is not verified, the system shall open no Group, show the message "Verify your e-mail to continue" and offer a button that sends the verification e-mail again. | Q-47 |
| R-001-05 | If the e-mail or the password is wrong, then the system shall show the single message "E-mail or password is wrong" without saying which one was wrong [ASSUMPTION: avoids revealing which addresses are registered]. | Q-47 |
| R-001-06 | If the password at registration has fewer than 8 characters, then the system shall create no account and show the rule next to the password field. | Q-47 |
| R-001-07 | If the e-mail address at registration is already registered, then the system shall create no account and offer "Sign in" and "Reset password". | Q-47 |
| R-001-08 | When a visitor asks to reset the password, the system shall start Firebase's reset e-mail flow and show the same confirmation whether or not the address is registered [ASSUMPTION]. | Q-47 |
| R-001-09 | While the Firebase session of a User is valid, the system shall keep the User signed in after the page is reloaded. | Q-47 |
| R-001-10 | When a User signs out, the system shall end the session and show the sign-in page. | Q-47 |
| R-001-11 | When the system receives a valid Firebase ID token of a person it does not know yet, it shall create the User with the Firebase identifier, the e-mail in lowercase and the display name. | Q-39 |
| R-001-12 | If the Firebase ID token of a User has expired or is invalid, then the system shall return the User to the sign-in page. | Q-39 |

## Acceptance criteria

| ID | Given | When | Then | Rules |
|---|---|---|---|---|
| AC-001-01 | No account for `ana@acme.com` | A visitor registers with display name `Ana Novak`, `ana@acme.com` and password `Geslo1234` | An account exists, a verification e-mail is sent, the page asks to verify the e-mail and no Group is opened | R-001-01, R-001-04 |
| AC-001-02 | `ana@acme.com` has a verified e-mail | Ana signs in with the correct password | The Group list opens and a User with e-mail `ana@acme.com` and display name `Ana Novak` exists | R-001-03, R-001-11 |
| AC-001-03 | A Google profile named `Janez Kos` with a verified e-mail | The visitor chooses "Sign in with Google" | The visitor is signed in, the display name is `Janez Kos` and the Group list opens | R-001-02, R-001-03 |
| AC-001-04 | Ana is signed in with an unverified e-mail | She tries to open the Group list | The message "Verify your e-mail to continue" and the resend button are shown, and no Group is shown | R-001-04 |
| AC-001-05 | `ana@acme.com` is registered | Someone signs in with a wrong password | The message "E-mail or password is wrong" is shown and nobody is signed in | R-001-05 |
| AC-001-06 | No account for `new@acme.com` | A visitor registers with the password `Abc1234` (7 characters) | No account is created and the password rule is shown next to the field | R-001-06 |
| AC-001-07 | `ana@acme.com` is registered | A visitor registers with `ana@acme.com` | No second account is created and "Sign in" and "Reset password" are offered | R-001-07 |
| AC-001-08 | Any visitor | The visitor asks to reset the password for `nobody@acme.com`, then for `ana@acme.com` | Both times the same confirmation text is shown; Firebase sends the reset e-mail only to the registered address | R-001-08 |
| AC-001-09 | Ana is signed in | She reloads the page | She is still signed in | R-001-09 |
| AC-001-10 | Ana is signed in | She signs out | The sign-in page is shown and the Group list is no longer reachable without signing in | R-001-10 |
| AC-001-11 | Ana's token has expired | She makes a request | She is returned to the sign-in page | R-001-12 |

## Edge cases

| ID | Input or situation | Expected result | Rules |
|---|---|---|---|
| EX-001-01 | Password of exactly 8 characters | Account created | R-001-01 |
| EX-001-02 | Password of 7 characters | Refused (AC-001-06) | R-001-06 |
| EX-001-03 | Display name of 100 characters | Account created | R-001-01 |
| EX-001-04 | Display name of 101 characters, or empty | No account created; message next to the field | R-001-01 |
| EX-001-05 | E-mail `Ana@Acme.COM` at registration | Account created; the User's e-mail is stored as `ana@acme.com` | R-001-01, R-001-11 |
| EX-001-06 | E-mail `ana@` (invalid format) | No account created; message next to the field | R-001-01 |
| EX-001-07 | Google profile without a name | Display name is the e-mail address | R-001-02 |
| EX-001-08 | Password reset for an unregistered address | Same confirmation as for a registered one; nothing revealed | R-001-08 |
| EX-001-09 | Verified e-mail is the only difference from AC-001-04 (the User verifies and reloads) | The Group list opens | R-001-03, R-001-04 |

## Out of scope

Multi-factor authentication; providers other than e-mail with password and Google; company single sign-on; changing the e-mail address or password inside the product (only the reset flow); deleting the account (US-021); showing invitations (US-014); locking accounts after failed sign-ins beyond Firebase's own protection.
