# US-026 Merge duplicate Contacts

> For: agent (reads), human (reviews) · Owner: Product owner · Agent: read-only

Format: `general/requirements-standard.md`.

## Story

As an Owner or Editor, I want to merge duplicate Contacts field by field into one, so that my Group has each person once and nothing is lost by accident.

## Purpose

Finding duplicates only helps if they can be merged. A merge destroys information if done wrongly, so the user chooses every value, confirms, and can get the merged-away Contacts back from Trash for 30 days.

## Definitions

| Term | Meaning |
|---|---|
| Merge screen | The screen that shows the chosen Contacts side by side, field by field, with a choice of the value to keep. |
| Survivor | The oldest of the merged Contacts (by creation time); it stays and takes the chosen values. |
| Merged-away Contacts | The other Contacts of the merge; they go to Trash. |

## Rules

| ID | Rule (EARS) | Source |
|---|---|---|
| R-026-01 | When an Owner or Editor picks two or more Contacts from a Duplicate set and starts a merge, the system shall show the Merge screen with the chosen Contacts side by side, field by field. | Q-42 |
| R-026-02 | The system shall preselect for each field the first non-empty value of the Survivor, then of the next oldest Contacts, and shall let the user choose any other value of that field. | Q-42 |
| R-026-03 | The system shall combine the Tags of the merged Contacts into one set. | Q-42 |
| R-026-04 | The system shall combine the Attributes of the merged Contacts, and where the same key (ignoring case) has different values, shall let the user choose the value. | Q-42 |
| R-026-05 | When the user confirms the merge, the system shall give the Survivor the chosen values, raise its version number (BR-07) and move the merged-away Contacts to Trash (BR-04); nothing shall be merged without the confirmation. | Q-42 |
| R-026-06 | If the merged result does not follow BR-06, then the system shall merge nothing and show the reason. | Q-30, Q-42 |
| R-026-07 | When a merge is done, the system shall record one History entry that lists the merged Contacts and the chosen values (BR-03), and shall show the History of the merged-away Contacts also in the History of the Survivor. | Q-42 |
| R-026-08 | If one of the Contacts was changed or moved to Trash after the Merge screen was opened, then the system shall merge nothing and refuse as in BR-07. | Q-38, Q-42 |
| R-026-09 | If a merge request names only one Contact, or Contacts of different Groups, then the system shall merge nothing and refuse it. | Q-42 |
| R-026-10 | The system shall not offer an automatic merge without the user's choice. | Q-42 |
| R-026-11 | While a merged-away Contact has been in Trash for less than 30 days, the system shall let an Owner or Editor restore it (US-012). | Q-42 |
| R-026-12 | If a Viewer asks for a merge, then the system shall refuse (BR-02). | Q-42 |

## Edge cases

| ID | Input or situation | Expected result | Rules |
|---|---|---|---|
| EX-026-01 | Three Contacts merged | One Survivor; two in Trash; one History entry | R-026-05, R-026-07 |
| EX-026-02 | All three have the same value in a field | The value is preselected; no choice needed | R-026-02 |
| EX-026-03 | A and B have equal creation time | The Contact with the smaller internal id is the Survivor [ASSUMPTION] | R-026-02 |
| EX-026-04 | Combined Tags exceed 50 | Merge refused with the limit (BR-06 style limit of US-005) [ASSUMPTION] | R-026-03 |
| EX-026-05 | Combined Attributes exceed 50 pairs | Merge refused with the limit | R-026-04 |
| EX-026-06 | A Contact is merged with itself (same id twice) | Refused | R-026-09 |
| EX-026-07 | A Contact of the set is in Trash when merge starts | Refused | R-026-08 |
| EX-026-08 | Attribute keys `Kompetenca` and `kompetenca` | Treated as the same key | R-026-04 |
| EX-026-09 | Notes of 5,000 characters on A and B; user keeps both parts | The merged notes would exceed 5,000 characters, so refused [ASSUMPTION: text is not joined; the user chooses one] | R-026-06 |

## Out of scope

Automatic merge; merging Contacts of different Groups; merging Tags or Groups; un-merge other than restoring merged-away Contacts from Trash and restoring a Version (US-023).
