# US-014 Invite a person to a Group

> For: agent (reads), human (reviews) · Owner: Product owner · Agent: read-only

Format: `general/requirements-standard.md`.

## Story

As an Owner, I want to invite a colleague by e-mail address and give them a Role, so that we can work on the Contacts of the Group together.

## Purpose

A Group of one person is only a private list. Teams need shared Contacts, but without sharing them with strangers: only the person with the invited, verified e-mail address gets in. Priority and MVP are [ASSUMPTION]: the interview gives no priority; journey 2 of Q-54 needs it.

## Definitions

| Term | Meaning |
|---|---|
| Pending Invitation | An Invitation not yet accepted, cancelled or expired. |

## Rules

| ID | Rule (EARS) | Source |
|---|---|---|
| R-014-01 | When an Owner enters a valid e-mail address and a Role (Owner, Editor or Viewer [ASSUMPTION: all three may be offered]), the system shall create a pending Invitation for that e-mail address (lowercase) that expires 14 days after it was created. | Q-25, Q-48 |
| R-014-02 | If the e-mail address has no valid format, then the system shall create no Invitation and show a message next to the field. | Q-25 |
| R-014-03 | If the Group already has 20 pending Invitations, then the system shall create no Invitation and show the limit. | Q-48 |
| R-014-04 | If the e-mail address already belongs to a Member of the Group, or already has a pending Invitation to the Group [ASSUMPTION], then the system shall create no Invitation and say so. | Q-25 |
| R-014-05 | When a User whose e-mail is verified and equals (ignoring case, BR-05) the e-mail of a pending, unexpired Invitation opens the Group list, the system shall make the User a Member with the invited Role, mark the Invitation accepted and show the Group in the Group list; the User does not have to accept or decline [ASSUMPTION]. | Q-25 |
| R-014-06 | While the e-mail of a User is not verified, the system shall give no access to a Group through an Invitation. | Q-25, Q-47 |
| R-014-07 | When an Owner cancels a pending Invitation, the system shall mark it cancelled; a cancelled Invitation shall give no access. | Q-48 |
| R-014-08 | When an Invitation is 14 days old, the system shall treat it as expired; an expired Invitation shall give no access. | Q-48 |
| R-014-09 | When an Owner opens the Invitations of the Group, the system shall list the pending Invitations with e-mail address, Role and expiry date. | Q-48 |
| R-014-10 | If an Editor or Viewer tries to create or cancel an Invitation, then the system shall refuse (BR-02). | Q-08, Q-25 |
| R-014-11 | When an Invitation is created or cancelled, and when a User joins through it, the system shall record a History entry (BR-03). | Q-37 |
| R-014-12 | The system shall not send any e-mail itself about an Invitation [ASSUMPTION: no mail sending exists in the product, Q-33; the Owner tells the person]. | Q-33 |

## Acceptance criteria

| AC-014-02 | Same, Boris has a verified account | Boris signs in | `Acme` is in his Group list with Role Editor and the Invitation is accepted | R-014-05 |

| AC-014-06 | `boris@acme.com` is a Member | Ana invites `Boris@Acme.com` | No Invitation; "already a Member" is shown | R-014-04 |

| AC-014-08 | An Invitation created 14 days ago | The invited person signs in | `Acme` is not in the list | R-014-08 |
| AC-014-09 | Boris is an Editor | He calls the invite request | Refused; no Invitation | R-014-10 |
| AC-014-10 | An Invitation, its acceptance | — | The Group activity list shows the invitation and the joining | R-014-11 |
| AC-014-11 | The Invitation is created | — | The system has sent no e-mail | R-014-12 |

## Edge cases

| ID | Input or situation | Expected result | Rules |
|---|---|---|---|
| EX-014-01 | 19 pending, then one more | Created (20th) | R-014-03 |
| EX-014-02 | 20 pending, one expires, then a new one | Created (expired ones do not count) | R-014-03, R-014-08 |
| EX-014-03 | Invitation 13 days 23 hours old | Still valid | R-014-08 |
| EX-014-04 | Invitation exactly 14 days old | Expired | R-014-08 |
| EX-014-05 | Pending Invitation for an address; the same address is invited again | Refused | R-014-04 |
| EX-014-06 | E-mail typed as `  BORIS@ACME.COM ` | Stored as `boris@acme.com` | R-014-01 |
| EX-014-07 | The invited person registers after the Invitation was made, then verifies | `Acme` appears after verification | R-014-05, R-014-06 |
| EX-014-08 | The invited address is the Owner's own address | Refused: already a Member | R-014-04 |
| EX-014-09 | A person signs in with a different verified address | No access | R-014-05 |

## Out of scope

Invitation links; sending e-mail; declining an Invitation; resending an Invitation (create a new one); inviting a person to several Groups at once; administrator adding.
