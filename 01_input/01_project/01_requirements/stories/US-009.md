# US-009 Filter Contacts

> For: agent (reads), human (reviews) · Owner: Product owner · Agent: read-only

Format: `general/requirements-standard.md`.

## Story

As a Member, I want to narrow the contact list by Tags, country, company and Attributes, so that I see exactly the Contacts I need, for example all participants of 2025 who may be notified.

## Purpose

Tags and Attributes are only useful if they can be used to select Contacts. The tag `neObvescaj` must be excludable, so that a user preparing a list for other tools leaves those people out.

## Definitions

| Term | Meaning |
|---|---|
| Filter | One condition on the contact list; all active filters and the search text apply together (AND). |
| Without-Tags filter | Keeps the Contacts that carry none of the chosen Tags. |

## Rules

| ID | Rule (EARS) | Source |
|---|---|---|
| R-009-01 | When a Member chooses one or more Tags and the mode "has all of these Tags", the system shall show only the Contacts that carry every chosen Tag. | Q-31 |
| R-009-02 | When a Member chooses one or more Tags and the mode "has any of these Tags", the system shall show only the Contacts that carry at least one chosen Tag. | Q-31 |
| R-009-03 | When a Member chooses one or more Tags in the Without-Tags filter, the system shall show only the Contacts that carry none of them. | Q-32 |
| R-009-04 | When a Member chooses a country, the system shall show only the Contacts with that country. | Q-35 |
| R-009-05 | When a Member chooses a company from the companies used in the Group, the system shall show only the Contacts whose company equals it ignoring case and accents (BR-05) [ASSUMPTION: one company at a time, chosen from a list]. | Q-35 |
| R-009-06 | When a Member enters an Attribute key and a value, the system shall show only the Contacts that have an Attribute with that key (ignoring case) and that value (ignoring case) [ASSUMPTION: one Attribute filter at a time]. | Q-34, Q-35 |
| R-009-07 | When a Member chooses an Attribute key with "exists", the system shall show only the Contacts that have an Attribute with that key (ignoring case). | Q-34 |
| R-009-08 | The system shall combine all active filters and the search text with AND. | Q-35 |
| R-009-09 | When a filter changes, the system shall show page 1 and the number of matching Contacts. | Q-35 |
| R-009-10 | When a Member chooses "Clear filters", the system shall remove all filters and the search text. | Q-35 |
| R-009-11 | The system shall offer only Tags, companies, countries and Attribute keys that occur in the open Group. | Q-20 |
| R-009-12 | If no Contact matches, then the system shall show "No contacts match" and a "Clear filters" button. | Q-35 |

## Acceptance criteria

| ID | Given | When | Then | Rules |
|---|---|---|---|---|
| AC-009-01 | A has Tags `a`,`b`; B has `a`; C has `b` | Filter "has all" of `a`,`b` | Only A | R-009-01 |
| AC-009-02 | Same | Filter "has any" of `a`,`b` | A, B and C | R-009-02 |
| AC-009-03 | A has `udelezenec2025`; B has `udelezenec2025` and `neObvescaj` | Filter "has all" `udelezenec2025` and Without-Tags `neObvescaj` | Only A | R-009-01, R-009-03, R-009-08 |
| AC-009-04 | Contacts in `SI` and `AT` | Country filter `SI` | Only the `SI` Contacts | R-009-04 |
| AC-009-05 | Contacts with company `Acme d.o.o.` and `Beta` | Company filter `Acme d.o.o.` | Only the Acme Contacts | R-009-05 |
| AC-009-06 | A has `kompetenca=spletnoProgramiranje`; B has `kompetenca=java`; C has none | Attribute filter `kompetenca` equals `java` | Only B | R-009-06 |
| AC-009-07 | Same | Attribute filter `kompetenca` exists | A and B | R-009-07 |
| AC-009-08 | Filter and search text active | The Member types search text | The result must satisfy both | R-009-08 |
| AC-009-09 | Filters active; page 2 shown | A filter is changed | Page 1 and the new count are shown | R-009-09 |
| AC-009-10 | Filters active | The Member chooses "Clear filters" | The full list is shown | R-009-10 |
| AC-009-11 | `Beta` has Tag `gost`; the Member opens `Acme` | The Member opens the Tag filter | `gost` is not offered | R-009-11 |
| AC-009-12 | No Contact has the Tag `x` | Filter by Tag `x` | "No contacts match" and "Clear filters" | R-009-12 |

## Edge cases

| ID | Input or situation | Expected result | Rules |
|---|---|---|---|
| EX-009-01 | No Tag chosen in the Tag filter | No Tag filtering | R-009-01 |
| EX-009-02 | Same Tag in "has all" and in Without-Tags | No Contact matches | R-009-08 |
| EX-009-03 | Contact without Attributes under "exists" | Not listed | R-009-07 |
| EX-009-04 | Attribute value filter `JAVA` against `java` | Matches (ignoring case) | R-009-06 |
| EX-009-05 | Contact without country under a country filter | Not listed | R-009-04 |
| EX-009-06 | A Contact in Trash carries the chosen Tag | Not listed | R-009-01 |
| EX-009-07 | Company `Čeh d.o.o.` filter vs. stored `Ceh d.o.o.` | Matches (ignoring accents) | R-009-05 |

## Out of scope

Saved filters; filter by phone, city, job title or notes; several Attribute filters at once; filter by creation date; filtering across Groups.
