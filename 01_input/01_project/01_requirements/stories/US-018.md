# US-018 Secured REST interface and Group isolation

> For: agent (reads), human (reviews) · Owner: Product owner · Agent: read-only

Format: `general/requirements-standard.md`.

## Story

As a Member, I want every request to the system's REST interface to be checked for who I am and what my Role allows, so that nobody who is not a Member of my Group can see or change its Contacts.

## Purpose

"Data of different users and their projects must be isolated" (the brief). The browser UI and any other client reach the data only through this interface, so isolation is decided here. One leak breaks the product's main promise.

## Definitions

| Term | Meaning |
|---|---|
| Endpoint | One operation of the REST interface (method and path). |
| Health check | The one endpoint that needs no sign-in; it reports only whether the system runs. |
| Error format | The one JSON shape of every error: a machine-readable code, a short message, no stack trace. |

## Rules

| ID | Rule (EARS) | Source |
|---|---|---|
| R-018-01 | If a request to any endpoint other than the health check has no Firebase ID token in the `Authorization: Bearer` header, or the token is invalid or expired, then the system shall answer 401 and return no data. | Q-39 |
| R-018-02 | If a request concerns a Group of which the signed-in User is not a Member, then the system shall answer 404 and return no data, whatever the endpoint (BR-01). | Q-39, Q-48 |
| R-018-03 | If a Member whose Role is not allowed to do the action (BR-02) sends a request, then the system shall answer 403 and change nothing. | Q-39 |
| R-018-04 | The system shall take the Group of a request only from the request path and shall ignore or reject any Group named in the request body. | Q-39 |
| R-018-05 | If a request names a Contact, Tag or other object that does not belong to the Group in the path, then the system shall answer 404 and return no data. | Q-48 |
| R-018-06 | While the e-mail of the signed-in User is not verified, the system shall answer 403 to every request about a Group. | Q-47 |
| R-018-07 | When the health check is called without a token, the system shall answer that it is running and return no other information. | Q-39 |
| R-018-08 | The system shall publish an OpenAPI description of the REST interface. | Q-39 |
| R-018-15 | The system shall exchange JSON in the REST interface. | Q-39 |
| R-018-09 | If a request fails, then the system shall answer in the error format without a stack trace. | Q-39 |
| R-018-10 | If a User sends more than 100 requests within one minute, then the system shall answer 429 to the further requests of that User until the minute has passed. | Q-39 |
| R-018-11 | If a request body is larger than 1 MB, then the system shall refuse it and store nothing. | Q-39 |
| R-018-12 | The system shall accept requests over HTTPS only. | Q-39 |
| R-018-16 | The system shall accept cross-origin browser requests only from the origin of its own front end. | Q-39 |
| R-018-13 | When a request fails authentication, is answered 401, 403 or 404, or is limited by the rate limit, the system shall write a log line without Contact data and without tokens. | Q-48 |
| R-018-14 | The system shall store and show text entered by users, such as a Contact named `<script>alert(1)</script>`, as plain text. | Q-48 |

## Acceptance criteria

| ID | Given | When | Then | Rules |
|---|---|---|---|---|
| AC-018-01 | Any Contact endpoint | Called without a token | 401, no data | R-018-01 |
| AC-018-02 | Same | Called with a token of a deleted account or an expired token | 401, no data | R-018-01 |
| AC-018-03 | Ana owns `Acme` with Contacts; Boris is signed in and is no Member | Boris requests `GET /groups/{Acme id}/contacts` | 404 and a body without any Contact data | R-018-02 |
| AC-018-04 | Same | Boris calls every endpoint of the REST interface that has a Group in its path with `Acme`'s id | Every one answers 404 and no data | R-018-02 |
| AC-018-05 | Viola is a Viewer in `Acme` | She calls an export, a create and a Trash endpoint | 403 each; nothing changes | R-018-03 |
| AC-018-06 | Ana is Owner of `Acme` and `Beta` | She creates a Contact in `Acme` with `group: Beta` in the body | The Contact is created in `Acme` (or the request is rejected), and never in `Beta` | R-018-04 |
| AC-018-07 | Ana is Owner of `Acme` and `Beta`; Contact C is in `Beta` | She requests C under `/groups/{Acme id}/contacts/{C id}` | 404 | R-018-05 |
| AC-018-08 | The signed-in User's e-mail is unverified | A Group endpoint is called | 403 | R-018-06 |
| AC-018-09 | No token | The health check is called | 200 with the status and nothing else | R-018-07 |
| AC-018-10 | The system runs | The OpenAPI description is requested | A valid OpenAPI document that lists every endpoint | R-018-08 |
| AC-018-17 | Any endpoint with a body | A request is sent with a non-JSON body | Refused in the error format | R-018-15 |
| AC-018-11 | Any error | — | The body has a code and a message and no stack trace | R-018-09 |
| AC-018-12 | A User sent 100 requests in the last minute | The 101st arrives | 429 in the error format; after the minute requests work again | R-018-10 |
| AC-018-13 | A body of 1 MB + 1 byte | It is sent to a create endpoint | Refused; nothing stored | R-018-11 |
| AC-018-14 | A plain HTTP request; a request with `Origin: https://evil.example` | — | The plain request is refused; the foreign origin gets no CORS permission | R-018-12, R-018-16 |
| AC-018-15 | Failed requests of AC-018-01, 03, 05 and 12 | The server log is read | One line per event; no Contact data, no token | R-018-13 |
| AC-018-16 | A Contact with last name `<script>alert(1)</script>` | It is listed and opened | The text is displayed as typed; no script runs | R-018-14 |

## Edge cases

| ID | Input or situation | Expected result | Rules |
|---|---|---|---|
| EX-018-01 | A Group id that does not exist | 404, same body as for a Group the User is not a Member of | R-018-02 |
| EX-018-02 | A malformed Group id (`abc`) | 404 in the error format | R-018-02, R-018-09 |
| EX-018-03 | Exactly 100 requests in a minute | All accepted | R-018-10 |
| EX-018-04 | Body of exactly 1 MB | Accepted | R-018-11 |
| EX-018-05 | A Member who was just removed | 404 on the next request | R-018-02 |
| EX-018-06 | Method not allowed on a path | 405 in the error format | R-018-09 |
| EX-018-07 | Token of another Firebase project | 401 | R-018-01 |
| EX-018-08 | A user with a token sends a request for a Group in Trash | 404 | R-018-02 |
| EX-018-09 | Two different Users send 100 requests each | Neither is limited | R-018-10 |

## Out of scope

API keys or other ways for tools to call the interface (Q-39: later story); real-time channels; public endpoints other than the health check; IP-based blocking.
