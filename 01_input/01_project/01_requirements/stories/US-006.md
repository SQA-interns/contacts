# US-006 Rename and delete a Tag

> For: agent (reads), human (reviews) · Owner: Product owner · Agent: read-only

Format: `general/requirements-standard.md`.

## Story

As an Owner or Editor, I want to rename or delete a Tag for the whole Group, so that I can fix a misspelt Tag or retire a category without editing every Contact.

## Purpose

A Tag typed wrongly on 200 Contacts would otherwise need 200 edits. Deleting a Tag must never delete Contacts.

## Definitions

| Term | Meaning |
|---|---|
| Tag list | The screen that lists the Tags of the Group with the number of Contacts that have each [ASSUMPTION: the interview gives the actions, not the screen]. |

## Rules

| ID | Rule (EARS) | Source |
|---|---|---|
| R-006-01 | When an Owner or Editor opens the Tag list, the system shall show every Tag of the Group with the number of Contacts that carry it. | Q-31 |
| R-006-02 | When an Owner or Editor renames a Tag to a valid Tag name (US-005) that no other Tag of the Group has ignoring upper and lower case (BR-05), the system shall change the name on all Contacts that carry the Tag. | Q-31 |
| R-006-03 | If the new name is not a valid Tag name or equals another Tag of the Group ignoring case, then the system shall change nothing and show the reason. | Q-31 |
| R-006-04 | When an Owner or Editor renames a Tag to a name that differs from the old name only in upper and lower case, the system shall change the spelling. | Q-31 |
| R-006-05 | When an Owner or Editor confirms the deletion of a Tag, the system shall remove the Tag from all Contacts, including Contacts in Trash [ASSUMPTION], and delete the Tag, and shall delete no Contact. | Q-31 |
| R-006-06 | Before deleting a Tag, the system shall ask for confirmation and show how many Contacts carry the Tag. | Q-31 |
| R-006-07 | When a Tag is renamed or deleted, the system shall record one History entry per affected Contact with the old and new name (BR-03) and shall not change the version numbers of those Contacts (BR-07). | Q-13 |
| R-006-08 | If a Viewer tries to rename or delete a Tag, then the system shall refuse (BR-02) and change nothing. | Q-08 |

## Acceptance criteria

| ID | Given | When | Then | Rules |
|---|---|---|---|---|
| AC-006-01 | Tag `udelezenec2025` is on 3 Contacts | Ana renames it to `udelezenec2026` | All 3 Contacts show `udelezenec2026`; the Tag list shows 3 Contacts for it | R-006-01, R-006-02 |
| AC-006-02 | Tags `gost` and `udelezenec2025` exist | Ana renames `gost` to `UDELEZENEC2025` | Nothing changes; the reason is shown | R-006-03 |
| AC-006-03 | Tag `gost` exists | Ana renames it to `Gost` | The Tag is now spelt `Gost` | R-006-04 |
| AC-006-04 | Tag `gost` is on 5 Contacts | Ana opens the deletion, sees "5 contacts", and confirms | The Tag is gone from all 5 Contacts; all 5 Contacts still exist | R-006-05, R-006-06 |
| AC-006-05 | Tag `gost` is on 5 Contacts | Ana opens the deletion and cancels | Nothing changes | R-006-06 |
| AC-006-06 | Tag `gost` is on 2 Contacts, one at version 4 | Ana renames it | Each of the 2 Contacts has one new History entry; the version number of the Contact is still 4 | R-006-07 |
| AC-006-07 | Viola is a Viewer | She sends a rename request | Refused; nothing changes | R-006-08 |

## Edge cases

| ID | Input or situation | Expected result | Rules |
|---|---|---|---|
| EX-006-01 | New name of 50 / 51 characters | Accepted / refused | R-006-03 |
| EX-006-02 | New name with a space | Refused | R-006-03 |
| EX-006-03 | A Tag that no Contact carries is deleted | Deleted; no History entries | R-006-05 |
| EX-006-04 | A Contact in Trash carries the Tag; the Tag is deleted; the Contact is restored | The restored Contact does not have the Tag | R-006-05 |
| EX-006-05 | Rename to the same spelling | Nothing changes; no History entries | R-006-02 |
| EX-006-06 | A Tag of another Group is requested by id | Not found (BR-01) | R-006-02 |

## Out of scope

Merging two Tags; bulk Tag operations on a Selection; Tag colours; undoing a Tag deletion (restore the Contact from Trash does not bring the Tag back).
